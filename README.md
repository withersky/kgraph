# kgraph

Визуализатор knowledge graph из файлов [mcp-memory](https://github.com/modelcontextprotocol/servers) (JSONL) — превращает записи `entity` / `relation` в интерактивный граф на [vis.js](https://visjs.org) прямо в браузере.

Один скрипт без единой зависимости сверх стандартной библиотеки Python.

![static](https://img.shields.io/badge/python-3.8%2B-blue) ![platform](https://img.shields.io/badge/platform-linux%20%7C%20macos%20%7C%20windows-lightgrey) [![license](https://img.shields.io/badge/license-GPL--3.0-blue)](LICENSE)

## Возможности

- **Два режима**: разовая генерация статичного `.html` и live-сервер с автообновлением.
- **Живой граф**: поиск узла с подсветкой соседей, клик по узлу — карточка с observations, размер узла зависит от числа связей, цвет — от типа сущности.
- **Легенда-фильтр** по типам сущностей с количеством узлов (клик по типу скрывает/показывает его).
- **Тёмная и светлая темы** с переключателем в шапке; в serve-режиме тема синхронизируется между всеми открытыми окнами и запоминается между запусками.
- **Несколько графов одновременно** — фоновые серверы, каждый на своём свободном порту.
- **Кросс-платформенность**: Linux, macOS, Windows (пути состояния и управление процессами заточены под каждую ОС).
- **Устойчив к реальным данным**: переживает «склеенные» без перевода строки записи (`}{`) и недописанный хвост файла, который дописывается на лету.
- **Экспорт в Obsidian**: конвертирует граф в набор Markdown-заметок с YAML-метаданными и вики-ссылками (односторонняя синхронизация из MCP в Obsidian).
- Встроенный `man`-страница прямо из CLI (`kgraph man`).

## Требования

- **Python 3.8+** — только стандартная библиотека, ничего устанавливать не нужно.
- Браузер.
- Интернет при **первом** открытии страницы: vis.js подгружается с CDN (unpkg).

## Установка

```sh
# скачать скрипт и сделать исполняемым
curl -L -o kgraph https://example.com/kgraph   # или скопировать вручную
chmod +x kgraph
mv kgraph ~/.local/bin/        # или в любую папку из PATH

kgraph -v
```

## Быстрый старт

```sh
# разовый HTML рядом с исходным файлом и сразу открыть
kgraph static notes.jsonl -o

# live-режим: открывает http://127.0.0.1:8765/ и сам обновляется при записи в файл
kgraph serve notes.jsonl
```

## Формат входного файла

JSONL с записями типов `entity` и `relation` (схема сервера mcp-memory):

```jsonl
{"type": "entity", "name": "withersky", "entityType": "person", "observations": ["Автор kgraph"]}
{"type": "entity", "name": "kgraph", "entityType": "tool", "observations": ["Визуализатор knowledge graph"]}
{"type": "relation", "from": "withersky", "relationType": "created", "to": "kgraph"}
```

Неполный хвост (файл ещё дописывается) не ломает рендер — страница просто помечает данные как неполные.

## Команды

| Команда | Описание |
|---|---|
| `kgraph <graph.jsonl>` | Сокращение для `static` (обратная совместимость) |
| `kgraph static <graph.jsonl> [-o \| --open]` | Пишет `<graph>.html` рядом с исходником. `-o/--open` сразу открывает в браузере |
| `kgraph obsidian <graph.jsonl> [-o DIR \| --out DIR]` | Экспортирует граф в Markdown-заметки для Obsidian (YAML + вики-ссылки) в каталог, по умолчанию `<graph>.obsidian` рядом с исходником |
| `kgraph serve <graph.jsonl> [-p N \| --port N] [-no \| --no-open] [-b \| --background]` | Live-режим. Порт по умолчанию `8765`. `-no` запрещает автозапуск браузера, `-b` уводит сервер в фон |
| `kgraph list` (алиас `ps`) | Показывает фоновые серверы: id, pid, порт, время старта, url |
| `kgraph stop <id \| порт \| имя> [--all \| -a]` | Останавливает сервер по id (например `notes-8765`), порту или части имени файла. `--all` — все сразу |
| `kgraph man` | Показывает man-страницу |
| `kgraph -v \| --version` | Версия и автор |

### Примеры

```sh
kgraph static notes.jsonl -o
kgraph obsidian notes.jsonl
kgraph obsidian notes.jsonl -o ~/Notes/KGraph
kgraph serve notes.jsonl                    # передний план, Ctrl+C останавливает
kgraph serve notes.jsonl -p 9000 -b         # фон на порту 9000
kgraph serve notes.jsonl --no-open          # не открывать браузер
kgraph ps
kgraph stop notes-9000
kgraph stop --all
```

## Режим static

Одноразово генерирует `<graph>.html` рядом с исходным JSONL. Страница полностью автономна после загрузки. Тема, выбранная при генерации, «запекается» в файл, а дальнейшие переключения браузер запоминает в `localStorage`.

## Режим obsidian

Одноразово конвертирует граф в набор Markdown-заметок для Obsidian:

- Каждая сущность — отдельный файл `<имя>.md` с YAML-фронтматтером (`type`, `tags`, при переименовании файла — `aliases`) и телом: observations списком и секция «Связи» с вики-ссылками `[[...]]` (входящие/исходящие направления и тип связи).
- Небезопасные для имени файла символы заменяются на `_`; оригинальное имя сохраняется в `aliases`, поэтому ссылки не теряются.
- Синхронизация однонаправленная: из MCP в Obsidian. Если вы измените что-то в Obsidian, MCP-сервер об этом не узнает.

```sh
kgraph obsidian notes.jsonl
kgraph obsidian notes.jsonl -o ~/Notes/KGraph
```

## Режим serve

Поднимает локальный HTTP-сервер на `127.0.0.1`. Страница опрашивает исходный файл каждые ~1.5 секунды и сама обновляется, когда в него пишут (удобно, когда MCP-сервер дописывает граф в реальном времени).

- **Передний план** (по умолчанию): если порт занят — честная ошибка с подсказкой указать `--port` или уйти в фон.
- **Фон** (`-b`): подбирает первый свободный порт, начиная с указанного, и возвращает управление в терминал. Серверы регистрируются в `servers.json` и видны через `kgraph list` / `kgraph ps`.
- Несколько графов могут работать одновременно — каждый со своим портом и id.

## Тема

По умолчанию светлая. В шапке страницы — переключатель 🌙/☀️.

- **serve**: выбор темы сохраняется в `servers.json` (ключ `_config.theme`) и мгновенно синхронизируется между всеми открытыми окнами графа. Эта же тема становится стартовой при следующей генерации статики.
- **static**: переключение запоминается браузером для этой страницы; стартовая тема берётся из `servers.json`, если файл есть.

Тема хранится отдельно от процессов — сменил, остановил, перезапустил — останется выбранная.

## Файлы состояния

Состояние хранится в каталоге, зависящем от ОС:

| ОС | Каталог |
|---|---|
| Linux | `$XDG_STATE_HOME/kgraph` (по умолчанию `~/.local/state/kgraph`) |
| macOS | `~/Library/Application Support/kgraph` |
| Windows | `%LOCALAPPDATA%/kgraph` (по умолчанию `~/AppData/Local/kgraph`) |

Внутри: `servers.json` (запущенные серверы + тема) и подкаталог `logs/` с логами фоновых серверов. Каталог создаётся автоматически при первом запуске — ничего настраивать не нужно.

## Интерфейс страницы

- **Заголовок окна (таб)**: `Kgraph - <имя файла>`.
- **Шапка страницы**: `Knowledge Graph — <полный путь к файлу>`, справа — количество узлов и связей, переключатель темы, поиск.
- **Поиск**: подсвечивает найденный узел и всех его соседей.
- **Клик по узлу**: панель с типом и observations.
- **Легенда**: слева внизу, сворачивается по клику на заголовок.
